## 2. Log / evidence capture: scripts/evox2/collect.sh
One command that produces halo-diag-<hostname>-<utc>.tar.gz, containing everything needed to judge a run, organized by directory, with a top-level manifest.json and SUMMARY.md (pass/fail/skip per step, exit codes, durations). Each step:
- runs with a timeout;
- never aborts the whole collection;
- records its exact command line, exit code, stdout, stderr and duration.

Steps:
- **System facts:** uname -a, /etc/os-release, lscpu, free, numactl -H, lsmem.
- **GPU and driver facts:**
  - dmesg amdgpu/kfd lines (with sudo if available, else note it);
  - rocminfo, rocm-smi --showall (and amd-smi if present), /opt/rocm/.info/version, hipconfig --full;
  - vulkaninfo --summary, and the full vulkaninfo to a file;
  - clinfo if present;
  - the kernel cmdline;
  - the amdgpu sysfs (pp_dpm_*, power_dpm_force_performance_level, gpu_busy_percent, mem_info_*, the gtt/vram sizes, hwmon temps/power);
  - the platform power profile if readable.
  - Capture thermal and power state before and after the whole run, and once per step if cheap.
- **HALO facts:** halo version; halo devices --verify --json; ldd of every binary.
- **All tests**, with gtest XML (--gtest_output=xml:...) per binary, and HIP/Vulkan device tests enabled. On the EVO-X2 they should RUN; that is the point. Include the opt-in full bandwidth benchmark (HALO_BANDWIDTH_FULL=1).
  - Also run the Vulkan tests once with RADV (select the RADV ICD explicitly via VK_DRIVER_FILES / VK_ICD_FILENAMES) and once with AMDVLK if installed.
  - Record the HIP/HSA env (HSA_OVERRIDE_GFX_VERSION must NOT be set; record it if it is).
- **With a model path given (--model <gguf> [--mtp <gguf>]):**
  - halo inspect --json;
  - a short greedy halo run at trace log level (at the current MVP stage this runs on the CPU engine; record which backend actually ran);
  - halo bench micro and model with --host-label and --power-mode from the args;
  - halo tune --list;
  - llama.cpp baselines if a llama.cpp build path is given.
  - Generation logs at the most verbose level HALO supports.
- **Structured and redacted.**
  - Every HALO log is at trace level, captured as JSON lines if log.h supports that. If it doesn't, add the minimal, additive support: env vars such as HALO_LOG_LEVEL, HALO_LOG_FORMAT=json and HALO_LOG_FILE, read at first use and documented in log.h.
  - Redact secrets (API keys, tokens) and anything matching *KEY*/*TOKEN*/*SECRET*/*PASSWORD* in env dumps.
  - Record hostnames and usernames only as given, with an --anonymize option.
- **Resource usage:** peak RSS and time per step (/usr/bin/time -v), plus the GPU memory used before and after (rocm-smi).
- **Triage-friendly output.** The bundle's SUMMARY.md must be written so an agent can triage it: first the failures and their log paths, then the expected-vs-actual checklist.
